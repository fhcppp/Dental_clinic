# ADR 0007 — Migration atomicity and canonical audit protocol

Status: Migration backup implemented / audit protocol pending. Date: 2026-11-01.

The sole schema authority remains `PRAGMA user_version`; migration v1 to v2 uses individual statements in `BEGIN IMMEDIATE`, never `executescript`. Before existing-version migration, SQLite's online backup API writes a consistent snapshot with a random filename in the original database directory, verifies `PRAGMA quick_check` and schema version and retains the copy for recovery. A failed migration rolls back its DDL, leaving original records and IDs unchanged. Downgrades are unsupported; SQLite backup copies are currently **plaintext test artifacts** and should never contain real patient data until database encryption is verified.

**Planned audit design, not yet implemented:** serialize UTF-8 canonical JSON (`sort_keys=True`, `separators=(',', ':')`, ASCII escaping disabled) with explicit version, monotonic sequence, UUID event ID, authenticated user, UTC ISO 8601 timestamp, action, entity kind/ID, redacted metadata, and predecessor digest. Compute SHA-256 over a domain-separated prefix plus canonical serialized event. Use an append-only table with unique sequence and `previous_hash`, and serialize concurrent writers with `BEGIN IMMEDIATE`. Insert the sensitive mutation and event in *the same SQLite transaction*. If event insertion or chain extension fails, roll back the business operation. Verify from a configured genesis hash through every row in sequence; fail closed on gaps, duplication, or mismatch. Cross-device tampering by an administrator remains possible without anchored signatures. Existing audit_events do not currently follow this scheme and must not be represented as tamper-evident.
